# The walking skeleton

Status: done, 2026-08-30

Every layer present, thin, and wired end to end, driven entirely by a synthetic
fixture fleet. Kept because this is where the shape of the project was decided;
the reasoning behind each choice is in `docs/decisions/`.

## What was built

- The project: Next.js App Router, TypeScript, Node 24, ESM, `quarterdeck-axi`.
- Six layers plus `src/providers/` and the `src/app/` composition point.
- `src/types/document.ts`, and the upstream contract pinned to
  `fm-fleet-snapshot.v1` and parsed at the boundary.
- Five synthetic fixture sets covering every degraded state the panel can reach.
- The server-render plus server-sent-events refresh loop.
- shadcn/ui themed to the product palette, light and dark, fonts vendored.
- Eight checks - the seven invariants plus `provider-bypass` - each with a
  planted violation proving the check works.
- The security baseline, in front of a write path that does not exist yet.
- `bin/quarterdeck`, on a port derived from the worktree path.

## Decision log

Decisions that came up while building, in the order they were settled. The
substantial ones have their own file in `docs/decisions/`.

1. **`src/app/` as a seventh position.** Invariant 6 and "pages live in
   `src/ui/`" cannot both hold. Route files became a position outside the six.
   See `2026-08-30-app-as-composition-point.md`.
2. **`src/domain/` may import `src/adapters/` type-only.** The alternatives -
   moving the upstream shape into `src/types/`, or duplicating it - were both
   worse. See `2026-08-30-layer-model.md`.
3. **No spawn provider yet.** The brief names logging, the clock and process
   spawning as the providers. Nothing in the skeleton spawns anything, and an
   interface with no implementation and no caller prevents nothing - invariant 3
   already bans `child_process` outside `intent.ts`. It joins `src/providers/`
   when something needs it.
4. **`config.allowedOrigins` deleted.** It was computed and never read; the
   request guard checks loopback host names directly. Found by the no-egress
   check firing on the `http://` literals it built, which is the check doing
   exactly its job on the first day.
5. **Tests drive `.next/standalone`, not `src/`.** A `tsc` build to `dist/` for
   unit tests was considered and dropped: two build outputs to keep in step, and
   the behavioural tests are better evidence anyway. Pure logic is exercised
   through the running server, with `QUARTERDECK_NOW` pinning the clock so
   staleness is deterministic. A freshness guard fails first if the build is old.
6. **`middleware.ts` renamed to `proxy.ts`.** Next 16 deprecates the old
   convention and warns on every build. Migrated rather than shipping a
   deprecation warning in the first commit.
7. **Scroll preservation demonstrated, not asserted.** See below.

## What was verified, and how

- `npm install && npm run build` from a clean clone on Node 24.
- `npm test`: lint, eight invariant checks against `src/` and against eight
  planted trees, and behavioural tests against the built server.
- The panel opened in a browser on its derived port, in light and dark.
- Acceptance 6, checked by hand in the browser rather than asserted in the
  suite: with the viewport scrolled to 200px and a DOM node marked with a
  `data-` attribute, editing a fixture changed the rendered content while both
  the scroll position and the marked node survived. A reload would have
  destroyed both, so this is direct evidence that React reconciled in place.

## What was deliberately left out

Reading a real fleet; the lifecycle rail, lane layout, embedded terminals,
filters and home switcher; the deck and shipshape lenses; the write path; any
publishing machinery.
